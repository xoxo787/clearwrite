## 무엇을 검사했나

테스트에는 **문서 전체 및 단일 편집 구간의 과도한 축약 차단**, 명시적 완화, 공백으로 분량 부풀리기 방지와 더불어 숫자·단위·%p·부정·가능성·비교 방향, 인용·코드·표·YAML·링크 보호, 원문 SHA-256 불일치, 편집 겹침과 모호한 위치, 변경량 초과, atomic 취소/safe-subset, 입력 크기, 잘못된 UTF-8/JSON, 출력 덮어쓰기·심볼릭 링크, 외부 전송 동의·키 누락·응답 오류, loopback/Host/Origin/CSRF, 설치 백업·재설치·카탈로그 보존이 포함됩니다.

테스트 수는 보안 인증이나 충분한 문체 품질의 지표가 아닙니다. 검사 중 발견한 비교 방향 변경, 긴/다중행 인용 보호, 모델 선택자의 URL 형태 문제를 수정하고 다시 실행했습니다. 결과 로그는 [TESTS.txt](validation/TESTS.txt), 실행 JSON은 [validation.json](validation/validation.json)에 있습니다.

## 브라우저 확인 범위

Chromium **144.0.7559.96**에서 갱신된 v0.1.1 화면의 분석, 윤문, JSON 저장, 원문 보존, 입력 HTML 비실행 5개 동작을 재확인했습니다. 자바스크립트 오류는 0개였습니다. [화면](ui-demo.png)과 [브라우저 기록](browser-validation.json)을 제공합니다.

**브라우저에서 loopback URL을 여는 동작은 제작 환경 관리자 정책으로 차단되었습니다.** 이를 우회하지 않았습니다. 페이지 DOM과 실제 편집 엔진은 in-process bridge로 연결해 검사했고, HTTP 서버의 Origin/CSRF/Host 경계는 unittest의 실제 로컬 소켓 요청으로 별도 검사했습니다. 따라서 이 결과를 브라우저→HTTP→엔진 전체 경로의 종단간 통과로 표시하지 않습니다.

옵션으로 Playwright/Chromium이 준비된 환경에서 `python scripts/browser_dom_check.py`를 실행할 수 있습니다. 이 검사는 기본 런타임 의존성이 아니며 브라우저를 자동 다운로드하지 않습니다. `CHROMIUM_PATH`로 실행 파일을 지정할 수 있습니다.

## 안전장치가 못 잡는 경우도 공개

[실제 대조 기록](validation/adversarial_cases.json)에 `7%p → 7%`, `30명 이상 → 30명 이하`, `may → will`이 거부되는 사례와, **도움을 준 주체와 받은 주체만 바꾸면 기계 검사를 통과하는 사각지대**를 함께 넣었습니다. 의미를 바꾸는 그 결과는 좋은 윤문이 아닙니다. 이 때문에 의미 동등성은 항상 `not_established`로 표시합니다.

## 비교 실험과 재현

[벤치마크](demo/BENCHMARK.md)는 웹 원문8 + 새 AI 글8 + 스트레스4를 사용한 실제 56회 적용 기록입니다. 내부 점수가 내려갔다고 인지 피로가 줄었다고 말할 수 없습니다. 모의 탐지 응답값도 벤치마크 실측에 합치지 않았습니다.

```sh
python -m unittest discover -s tests -v
python scripts/validate.py --out reports/local-validation
python scripts/benchmark.py --out reports/reproduced
```

새 wheel 검증은 `validate.py --wheel <wheel 경로>`를 추가합니다. 이때 wheel을 임시 가상 환경에 오프라인 설치합니다. 최초 검증 wheel SHA-256은 `eccedd215629772e7167bfc517ed3324a37a01e101383e4fb683da986483a822`입니다. 개인 계정 플러그인의 URL/식별자는 공개 소스에 포함하지 않았습니다. 등록 성공은 모든 호스트에서 설치·활성화·생성이 확인됐다는 뜻이 아닙니다.

## v0.1.1 회귀 사례

이전 예시는 마지막 문장을 원문 52자에서 26자로 압축했으며, 개별 구간 검사 부재로 통과했습니다. 새 엔진은 `excessive_local_compression`으로 이를 차단하고, 설명의 중요성을 유지한 새 제안은 승인했습니다. 전체 AI 한국어 예문은 417자 → 406자로 편집되어 (공백 제외 분량 비율 약 97.2%) 주요 설명을 유지합니다. 출처·해시·원문은 변경하지 않았습니다.

영어 AI 문맥 편집 제안 중 2건은 새 보존 검사에서 거부되어 원문으로 돌아갔습니다. 따라서 내부 문체 점수가 내려가지 않은 사례도 존재하며, 이를 숨기지 않고 벤치마크에 표시합니다. 보존 기준이 유용한 축약을 막을 가능성도 있으며 실제 독자 평가가 필요합니다.
