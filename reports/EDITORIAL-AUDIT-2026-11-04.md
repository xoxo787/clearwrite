# 윤문 스킬 보강 점검 기록

확인일: 2026-11-04. 환경: Windows, Python 3.14.6. 비교 기준 커밋: `8b454c597c7ad85af388b0217a8a26880601383b`.

프로젝트의 윤문 지침, 공통 모델 지시문, 보존 검사, 배포 번들을 보강했다. 기존 CLI와 제안 JSON 1.0은 유지한다. 개선한 규칙의 동작은 로컬에서 검증했지만 독자의 이해도나 모델 윤문 품질이 향상됐다고 측정한 것은 아니다.

## 확인한 문제와 수정

같은 원문·후보를 기준 커밋의 `core.py`와 수정한 엔진에 넣어 비교했다. 아래 사례의 기대 결과는 모두 차단이다. 원문 문장을 포함한 비교 JSON은 로컬 점검 기록에 보존했다.

| 문제 | 변조 사례 | 수정 전 관측 | 수정 후 관측 | 기대와 일치 |
| --- | --- | --- | --- | --- |
| 단위를 숫자와 함께 읽지 못함 | `10mg → 10g` | 통과 | `numbers_units_or_order_changed` | 예 |
| 한글 배율 누락 | `3천 원 → 3만 원` | 통과 | `numbers_units_or_order_changed` | 예 |
| 주장의 적용 범위 변경 | `일부 → 모든` | 통과 | `claim_qualifier_changed` | 예 |
| 조건 표지 수는 같지만 뜻이 반대 | `if → unless` | 통과 | `claim_qualifier_changed` | 예 |
| 관계 종류 변경 | `상관관계 → 인과관계` | 통과 | `claim_qualifier_changed` | 예 |

수량 검사는 복합 단위, 한글 배율, 긴 시간·횟수 단위, 단위 대소문자를 포함한다. 공백 변경은 허용한다. 주장 표지는 일부/전체/대부분, 숫자 앞 근사 표현, 예외, 상관/인과를 제한된 목록으로 검사한다. 개별 제안과 최종 문서를 모두 대조하며, safe-subset은 허용된 독립 제안을 계속 적용한다.

자동 검사만 강화하면 유효한 윤문까지 막을 수 있으므로, 단위 공백 정리·말투 변환·군더더기 수정이 허용되는 사례와 단어 접두부를 잘못 인식하지 않는 사례도 회귀 검사에 포함했다.

## 윤문 판단 보강

| 방법 | 반영한 내용 | 적용 경계 |
| --- | --- | --- |
| 독자와 문단 역할 파악 | 주장·근거·예시·조건을 먼저 살피고 문단 연결을 검토 | 필자의 서사나 모든 문단을 두괄식으로 바꾸지 않음 |
| 문장 호응 개선 | 주어와 서술어의 거리, 명사형 중첩·이중 피동, 지시 대상을 검토 | 주체나 지시 대상을 추측하지 않음 |
| 조건을 지키는 문장 분리 | 문장을 나눈 뒤에도 예외·부정·조건의 적용 범위를 유지 | 자동 표지 검사가 막으면 원문 표현을 유지 |
| 전문용어와 문체 일관성 | 같은 개념의 용어를 유지하고 강조 반복과 불필요한 중복을 구분 | 샘플의 경험·감정을 원문에 추가하지 않음 |
| 양방향 대조 | 원문에서 결과로는 누락, 결과에서 원문으로는 근거 없는 추가를 확인 | 같은 모델의 검토를 독립 의미 검증이라고 하지 않음 |
| 실제 적용본 재검토 | 일부 제안이 제외된 뒤에도 지시어·용어·문장 연결을 확인 | 제안 전체가 적용됐다고 가정하지 않음 |

공통 모델 지시문과 스킬에 같은 기준을 반영했다. [판단 예시](../skills/clearwrite/references/editing_examples.md)는 고칠 사례와 고치지 않을 사례를 함께 제공한다. `--term`은 prepare/apply에 함께 넘기고, `--voice`는 prepare에서 읽도록 기존 기능의 사용법도 명확히 했다.

## 조사 근거와 접근 범위

- [국립국어원·문화체육관광부, 쉬운 공공언어 쓰기 길잡이](https://www.korean.go.kr/front/etcData/etcDataView.do?etc_seq=399&mn_id=216): 독자의 처지와 이해 수준을 고려하는 원칙을 참고했다. 공식 게시글과 검색 색인에 표시된 머리말을 확인했으며, PDF 본문의 직접 추출은 웹 도구 접근 실패로 수행하지 못했다.
- [미국 국립문서기록관리청, Top 10 Principles for Plain Language](https://www.archives.gov/open/plain-writing/10-principles.html): 본문에서 독자 중심 정보 순서, 주어와 동사의 거리, 익숙한 표현을 확인했다. 능동태·짧은 문장을 모든 문맥에 강제하지 않도록 적용 범위를 제한했다.
- [Cripwell 외, Evaluating Document Simplification (READI 2024)](https://aclanthology.org/2024.readi-1.1/): 공식 초록에서 단순화와 의미 보존의 분리 평가 필요성을 확인했다. 이 관점을 검토 절차에 반영했으며, 논문의 지표 구현이나 효과 재현은 하지 않았다.

외부 글의 예문이나 전체 규칙을 복제하지 않았다. 새 판단 예문과 회귀 사례는 경계를 설명하기 위한 합성 자료다.

건너뛴 2개는 Windows 심볼릭 링크 권한 제한이다. 테스트 도중 기존 HTTP 헤더 거절 검사에서 `WinError 10053` 연결 중단이 두 차례 발생했다(`test_bad_token`, `test_wrong_content_type`). 본문을 읽기 전에 거절하는 동작을 확인하기 위해 기존 큰 요청 테스트와 같이 헤더만 보내도록 세 테스트를 조정했다. 403/415 응답과 본문을 기다리지 않는 조건을 유지하며 서버 동작은 바꾸지 않았다. 수정 뒤 관련 57개 검사와 전체 280개 검사를 통과했다. 실패 기록도 남겼다.

외부 스킬 검증기는 기본 CP949 디코딩에서 실패하여 `python -X utf8`로 재실행했다. 전역 Python 설정이나 검증기 파일은 변경하지 않았다. 변경한 Python 파일은 3.10 문법으로도 파싱했지만, Python 3.10 실행 검증을 대신하지는 않는다.

재현 명령:

```sh
python scripts/build_bundles.py
python scripts/build_bundles.py --check
python -m unittest discover -s tests -v
python scripts/benchmark.py --out reports/reproduced
git diff --check
```

실행 로그·수정 전 엔진·전후 비교 JSON·합성 윤문 시연·웹 탐색 기록은 실행별 `.clearwrite-runs/` 폴더에 보존했다. 벤치마크 결과는 `reports/reproduced/`에 있으며 두 디렉터리는 공개 배포 대상에서 제외된다.

## 수정 파일과 호환성

- 엔진: `src/clearwrite/core.py`.
- 스킬: `skills/clearwrite/SKILL.md`, `references/editorial_rules.md`, `references/editing_examples.md`.
- 번들 생성·검사: `scripts/build_bundles.py`, `data/bundle-source-hashes.json`, 생성된 skill/plugin 코드와 참조 문서.
- 테스트: `tests/test_preservation.py`, `tests/test_bundles.py`, `tests/test_integration.py`.
- 안내: README 한국어·영어, CHANGELOG, ARCHITECTURE, CLI, EVALUATION, 이 점검 기록.

CLI 옵션과 제안 스키마 1.0은 유지하며 데이터 이전은 필요 없다. 다만 기존에 통과하던 제안이 새 보존 검사에서 차단될 수 있고, 수량 배열은 더 완전한 단위·배율을 포함한다. 예를 들어 `1억 5천만 원`이 하나의 토큰으로 기록된다. 변경은 Unreleased로 기록했으며 공개 릴리스 번호를 올리지 않았다.

번들 생성은 디렉터리 전체 삭제를 없애고, 동기화 대상에 원본에 없는 파일이 있으면 보존한 채 오류를 낸다. 새 `--check`는 코드를 포함한 스킬 전체와 플러그인 스킬을 읽기 전용으로 대조한다.

## 남은 한계

- 제한된 표지·단위를 검사하므로 모든 의미 변화를 잡을 수 없다. 주어·목적어 교환, 표지 수는 같은데 적용 대상이 달라진 문장, 목록 밖 단위는 사각지대다.
- 동의어 변경이나 조건 반복처럼 유효한 수정도 보수적으로 거부할 수 있다. 모든 결과의 `semantic_equivalence: not_established`를 유지한다.
- 의미 보존과 가독성의 분리 검토는 지침으로 보강했지만 실제 모델 제안 품질에 대한 독립 실험은 수행하지 않았다.
- 이번 점검에서 실제 Codex/Claude/Ollama 요청, 외부 탐지기, 사람 독자 실험, macOS/Linux 실행, Windows 배포 EXE·브라우저 편집 화면의 재검증은 수행하지 않았다.
- 저장소와 배포용 번들을 수정했다. 전역 설치본 교체, 업로드, 푸시, 배포는 수행하지 않았다.
