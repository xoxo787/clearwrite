# ClearWrite · 맑은글 기능명세서

> 기준일: 2026-11-04  
> 대상: 현재 저장소의 소스 코드 — 0.4.0 + 2026-11-04 Unreleased 보강  
> 이 문서는 현재 구현을 설명합니다. 배포된 EXE나 전역 설치 스킬이 이 변경을 포함한다는 뜻은 아닙니다.

## 1. 제품 목적

한국어·영어 글의 의미, 설명 깊이, 필자의 말투를 보존하면서 불필요한 반복과 어색함을 다듬습니다. 원문·수정본·변경 이유를 연결해 사용자가 수정 내용을 확인하도록 돕습니다.

윤문은 요약과 구분합니다. 글이 짧아지거나 문체 점수가 낮아졌다는 이유만으로 더 좋은 결과라고 판정하지 않습니다. 수정할 필요가 없거나 보존 검사를 통과하지 못하면 원문을 유지합니다.

## 2. 제공 형태

| 형태 | 주요 사용자 흐름 | 모델 사용 |
| --- | --- | --- |
| 브라우저 편집 화면 | 글 붙여넣기 → 옵션 선택 → 윤문 → 전후 비교 → 복사·저장 | 설치된 Codex 또는 Claude Code CLI에 새 요청 |
| Windows 데스크톱 실행 파일 | EXE 실행 → 로컬 브라우저 편집 화면 열기 | 사용자가 설치하고 로그인한 CLI 사용 |
| Python CLI | UTF-8 파일·표준입력 → 분석·윤문·계획 적용·검증 → 텍스트·JSON | 기본은 로컬 규칙, 모델 백엔드는 명시적으로 선택 |
| Codex 스킬·플러그인 | 원문 보관 → prepare → 현재 모델의 제안 → apply → 최종 대조 | 현재 세션 모델 사용, Codex 중첩 실행 없음 |

소스 실행은 Python 3.10 이상이며 런타임 의존성은 표준 라이브러리입니다. Windows 배포본은 Python을 별도로 설치하지 않고 실행하는 형태입니다.

## 3. 기본 처리 흐름

```text
원문 입력
  → 편집 목적·강도·말투 선택
  → 로컬 규칙 또는 모델이 편집 제안 생성
  → 원문 위치·수량·조건·보호 구간·변경량 검사
  → 허용된 제안 적용 또는 원문 유지
  → 원문·수정본·이유 비교
  → 복사 / TXT 저장 / 검수 JSON 저장
```

문체 분석은 윤문과 별도 작업입니다. 원문만 분석하거나 현재 수정본과 함께 분석할 수 있으며, 분석 자체가 글을 다시 쓰지는 않습니다.

## 5. 편집 옵션

### 5.1 편집 목적

| 값 | 화면 표시 | 동작 기준 |
| --- | --- | --- |
| `personal` | 자연스럽게 | 이해 순서와 필요한 설명·예시를 보존하며 반복과 어색함 검토 |
| `publish` | 필자의 말투 유지 | 필자의 어조·논증·문단 흐름 유지 |
| `technical` | 기술 문서 | 전문용어·정의·단위·절차·조건·예외 우선 |
| `preserve` | 원문 보존 | 본문을 변경하지 않고 윤문 모델 요청 생략 |

### 5.2 편집자 페르소나

페르소나는 편집 정책이며 인물 연기 기능이 아닙니다. 아래 값은 별도 옵션으로 덮어쓰지 않았을 때의 기본값입니다.

| 값 | 이름 | 주요 개입 | 변경 예산 | 적용 정책 | 기본 말투 |
| --- | --- | --- | --- | --- | --- |
| `proofreader` | 꼼꼼한 교정자 | 맞춤법·띄어쓰기·조사·어미 오류·이중 피동 | 15% | 전체 적용 또는 전체 거절 | 원문 유지 |
| `editor` | 담백한 편집자 | 반복·늘어진 연결·상투적 예고 | 35% | 전체 적용 또는 전체 거절 | 원문 유지 |
| `formal` | 격식 있는 보고자 | 격식 있는 표현과 종결어미 | 50% | 통과한 제안만 적용 | 합니다체 |
| `columnist` | 칼럼니스트 | 관점 유지, 문장 재구성·리듬 개선 | 50% | 통과한 제안만 적용 | 원문 유지 |
| `plain` | 쉬운 말 해설가 | 쉬운 낱말과 문장 분리 | 50% | 통과한 제안만 적용 | 원문 유지 |
| `friendly` | 다정한 안내자 | 부드러운 안내 표현과 종결어미 | 50% | 통과한 제안만 적용 | 해요체 |

모든 페르소나에 동일한 정보 보존 검사를 적용합니다. 강한 페르소나도 새 사실·주체·경험을 추가하거나 주장의 강도를 바꿀 수 없습니다.

### 5.3 문법 스타일

- `keep`: 원문의 종결어미 유지.
- `hamnida`: 합니다체.
- `haeyo`: 해요체.
- `handa`: 한다체.

명시한 스타일은 페르소나 기본 말투보다 우선합니다. 말투를 변환하면 기본 변경 예산은 최소 35%, 적용 정책은 safe-subset이 됩니다. CLI에서 명시한 `--max-change`와 `--policy`가 있으면 해당 값이 우선합니다.

어미 일치율은 제한된 종결어미 규칙에 따른 비율입니다. 인용·코드·제목 등을 제외하며 문법 정확도 점수로 해석하지 않습니다. 개조식 변환은 구현되어 있지 않습니다.

## 6. 원문 보호와 적용 정책

| 검사 | 확인 내용 | 실패 시 처리 |
| --- | --- | --- |
| 원문 일치 | 원문 SHA-256, 정확한 원문 문자열, 유효한 위치, 제안 간 중복 여부 | 잘못되거나 오래된 계획 거절 |
| 수량 | 숫자 순서·부호·범위, 제한된 단위·배율·단위 대소문자 | `numbers_units_or_order_changed` |
| 주장 표지 | 부정·가능성·조건·의무·비교·증감 및 일부/전체·근사·예외·상관/인과 | 해당 보존 검사 실패 |
| 보호 구간 | 코드, 인용, Markdown 표·링크·일부 인용 표기, frontmatter, 지정 용어 등 | 구간 변경·겹침 거절 |
| 분량 | 문서 전체와 개별 제안의 과도한 축약 | 문서 또는 편집 구간의 압축 차단 |
| 변경 예산 | 원문과 후보의 문자 유사도를 이용한 변경률 | 허용 범위를 넘으면 차단 |

수량·주장 표지 보강 사례: `10mg → 10g`, `3천 원 → 3만 원`, `일부 → 모든`, `if → unless`, `상관관계 → 인과관계`를 거절합니다. 단위 공백 정리나 사실을 유지하는 표현 수정은 허용할 수 있습니다.

- **atomic:** 하나라도 거절된 제안이 있으면 전체 적용을 취소하고 원문을 반환합니다.
- **safe-subset:** 개별 검사에서 거절된 제안을 제외하고 나머지를 적용합니다. 이후 문서 전체 검사에 실패하면 원문으로 돌아갑니다.
- 최종 편집 상태는 `edited`, `unchanged`, `blocked`입니다. 입력·스키마 오류는 별도의 오류 응답입니다.
- 오프셋 없는 제안의 `original`은 원문에 정확히 한 번 있어야 합니다. 반복 문구는 주변 문맥을 함께 지정합니다.
- 공백 제외 문서 길이 100자 이상은 기본 85%, 50~99자는 70% 이상 보존을 요구합니다. 개별 수정 구간에도 별도 축약 기준이 있습니다. 자세한 예외와 계산은 [검사 구조](ARCHITECTURE.md)를 따릅니다.

검사는 완전한 의미 해석이 아닙니다. 주체 교환 등 일부 왜곡을 놓치거나 유효한 동의어 수정을 거절할 수 있습니다. 결과의 `semantic_equivalence`는 `not_established`로 유지합니다.

## 7. 문체 분석과 수정량

### 7.1 로컬 규칙 분석

한국어·영어의 좁은 24개 규칙으로 편집 후보를 찾습니다. 후보의 위치, 원문 표현, 규칙, 메시지, 자동 수정 가능 여부를 반환합니다. 규칙 점수와 읽기 부담 대리 지표는 휴리스틱이며 실제 인지 피로 측정값이 아닙니다.

### 7.2 모델 문체 분석

| 평가 항목 | 범위 |
| --- | --- |
| 같은 말·구조의 반복 | 0~25점 |
| 상투적인 연결·강조 | 0~25점 |
| 획일적인 문장 흐름 | 0~25점 |
| 구체성 없는 추상적 부연 | 0~25점 |

합계는 0~100점입니다. 입력 해시, 점수 범위, 실제 원문에 존재하는 인용 근거를 검사합니다. 각 평가에는 1~6개의 근거가 있으며 인용은 1~240자입니다. 검증 실패·취소·원문 변경 시 이전 점수나 임의의 0점을 표시하지 않습니다.

화면의 ‘AI 문체 분석’은 참고용 문체 평가이며 AI 작성 확률·작성률·저자 판별 기능이 아닙니다. 점수가 낮아지는 것을 윤문 완료 조건으로 삼지 않습니다.

### 7.3 실제 수정 비율

```text
(삭제·교체된 원문 글자 수 + 추가·대체된 글자 수)
÷ (원문 글자 수 + 결과 글자 수) × 100
```

공백과 줄바꿈을 포함한 Unicode 코드포인트 기준입니다. 실제로 적용된 수정이 없으면 0%입니다. 이 표시값은 편집 허용 여부를 결정하는 문자 유사도 기반 변경 예산과 구분합니다.

## 8. 화면과 파일 출력

- 원문, 수정본, 변경 이유를 세 영역으로 제공합니다. 좁은 화면에서는 세로로 배치합니다.
- 변경 구간이나 이유를 선택하면 세 영역이 해당 위치로 이동합니다. 클릭, Enter/Space, 이전·다음 수정 버튼을 지원합니다.
- 추가·삭제만 있는 위치에도 텍스트 내용에 포함되지 않는 표식을 제공합니다.
- 수정본은 클립보드로 복사하거나 `clearwrite-edited.txt`로 저장합니다.
- `clearwrite-report.json`에는 해당 작업의 원문, 수정본, 적용·거절 제안, 보존 검사, 수정량, 완료된 문체 분석 등을 담습니다. 원문만 분석한 경우에도 검수 JSON을 저장할 수 있습니다.
- 사용자가 원문을 바꾸면 이전 결과는 오래된 결과로 처리하며 새 입력에 대한 응답과 혼합하지 않습니다.
- 현재 화면에 수정별 수락·거절 버튼이나 결과 문서를 직접 편집하는 별도 편집기는 없습니다. 원문을 수정한 뒤 다시 윤문하는 흐름입니다.

| 모델 선택 | 이름을 직접 지정하거나 CLI 기본 모델 사용 |
| Ollama | 명시적으로 선택하는 로컬 loopback 연결, 모델 자동 설치·다운로드 없음 |
| 스킬 윤문 | 현재 호스트 모델의 제안과 포함된 Python 검사를 조합 |
| 요청 제한 | 시간·출력 한도, 취소, 동시 작업 제한 |
| 화면 서버 | `127.0.0.1` 로컬 접근, Host·Origin·CSRF 검사 |
| 원문 보관 | ClearWrite의 모델 연결은 원문·응답을 파이프로 전달하며 원문 임시 파일을 만들지 않음 |
| 서버 작업 기록 | 완료·실패·취소 후 기본 15분이 지나면 메모리 기록 만료, 앱 종료 시 정리 |
| 직접 저장한 파일 | 자동 삭제하지 않음. 검수 JSON은 원문을 포함하며 암호화하지 않음 |

화면에서 윤문과 모델 문체 분석은 각각 새 요청이며 요청마다 전송 동의를 확인합니다. 예시 체험·로컬 규칙 분석·원문 보존 윤문은 모델을 호출하지 않습니다. 모델 제공자와 CLI 자체의 저장·캐시 정책은 ClearWrite의 기록 만료 범위에 포함되지 않습니다.

스킬은 원문과 결과를 별도 UTF-8 파일로 보관하는 흐름이므로, 독립 프로그램의 모델 연결과 파일 보관 범위가 다릅니다. 입력 글 안의 명령·URL·셸 코드는 실행 지시로 취급하지 않습니다.

## 10. 입력 한도와 CLI 계약

| 항목 | 현재 한도·계약 |
| --- | --- |
| 원문 | 최대 12,000 Unicode 코드포인트. 화면 입력 요소도 길이를 제한함 |
| 문체 샘플 | 최대 3,000자 |
| 편집 제안 | 최대 80개, 서로 겹치지 않는 구간 |
| 보호 용어 | CLI 기준 최대 100개, 각 1~500자 |
| 변경 예산 | 0~50%, 페르소나 기본값 적용 |
| 출력 파일 | 원문 덮어쓰기 금지. 기존 출력 교체는 `--force` 필요 |
| JSON 계획 | 스키마 1.0, 필드·해시·자료형 검사 |
| CLI 종료 코드 | 0 완료, 2 편집·보존 검사 차단, 3 입력·파일·모델 오류, 130 사용자 중단 |

| 명령 | 기능 |
| --- | --- |
| `analyze` | 로컬 규칙 분석 |
| `rewrite` | 선택한 백엔드로 윤문 후 보호 검사·적용 |
| `prepare` | 현재 모델에 줄 원문·지시문·보호 구간·스키마 준비 |
| `plan` | 로컬 규칙의 위치 포함 편집 계획 생성 |
| `apply` | 전달된 계획 또는 오프셋 없는 제안 검사·적용 |
| `verify` | 원문과 후보의 보존 검사 |
| `detect` | 기본 로컬 문체 분석 또는 선택한 Codex/Claude 모델 문체 평가 |
| `serve` | 로컬 브라우저 편집 화면 실행 |
| `doctor` | 로컬 환경과 CLI 탐색 결과 확인 |

원문 유지 외 말투 변환과 적극적인 문맥 재작성은 모델 경로를 사용합니다. builtin은 `proofreader`·`editor`와 `style keep`만 지원합니다. 상세 옵션은 [CLI 안내](CLI.md)를 따릅니다.

## 11. 확인 가능한 완료 기준

| 시나리오 | 기대 결과 |
| --- | --- |
| 기본 로컬 윤문 | 외부 모델 없이 규칙 후보 수정, 원문 별도 유지 |
| 원문 보존 모드 | 윤문 모델 호출 없이 입력과 같은 결과 |
| Codex/Claude 전송 동의 없음 | 모델 요청 거절 |
| 단위 또는 주장 범위 변조 | 보존 검사에서 차단 |
| atomic에 유효·무효 제안 혼합 | 전체 적용 취소 |
| safe-subset에 독립적인 유효·무효 제안 혼합 | 유효 제안만 적용하고 문서 전체 검사 |
| 오래된 원문 해시 또는 모호한 제안 위치 | 적용 거절 |
| 요청 중 원문 변경 | 이전 응답이 새 입력 결과로 표시되지 않음 |
| 문체 분석 실패 | 점수 미분석 표시, 이미 얻은 윤문 결과 유지 |
| 결과 저장 | 원문과 결과 분리, 검수 JSON에 실제 적용 내역 기록 |

최근 2026-11-04 로컬 점검 기록은 전체 테스트 280개 중 278개 통과·2개 Windows 권한 관련 건너뜀, 오프라인 벤치마크 20문서·56회 적용 완료입니다. 이는 기능·계약·보존 규칙 검사 결과이며 실제 독자의 이해도나 새로운 모델 요청의 품질 검증이 아닙니다. [상세 점검 기록](../reports/EDITORIAL-AUDIT-2026-11-04.md)

## 12. 현재 제공하지 않는 범위

- AI 저자 판별, AI 작성률 인증, 외부 탐지기 회피 최적화.
- 모든 의미 변화·사실 오류를 찾아내는 자동 검증.
- 기본 동작으로서의 요약, 번역, 새 사실·경험 추가.
- DOCX·PDF 가져오기, OCR, 여러 문서 일괄 처리, 클라우드 동기화.
- 화면의 보호 용어·문체 샘플 입력 UI. 해당 기능은 CLI/스킬 경로에서 사용.
- 자동 저장 문서함, 공동 편집, 수정별 승인·거절 UI, 개조식 변환.
- 실제 독자 대상 가독성 효과나 모델 평가 점수의 정확도 보증.
