# GitHub 공유와 배포

원본 ZIP은 새 저장소로 공개할 수 있는 구조입니다. GitHub/PyPI 공개가 완료되었다는 뜻은 아닙니다. 사용자의 계정명·토큰·비공개 글을 패키지에 넣지 않습니다.

## 공개 전

`python -m unittest discover -s tests -v`로 검사하고 `python scripts/build_bundles.py`로 번들을 동기화합니다. 문서·라이선스·데이터 출처를 검토하세요. `reports`에는 실제 입력 원문이 들어 있으므로 개인 자료로 다시 돌린 보고서는 공개하지 마세요. `.gitignore`는 보조 장치이며 유출 방지를 보증하지 않습니다. 배포 도우미는 알려진 소스 폴더만 선택하고 경로·간단한 비밀 패턴을 검사하지만 독립 보안 스캐너가 아닙니다.

## 새 공개 저장소

로컬에 Git과 GitHub CLI를 설치하고 `gh auth login`을 완료합니다. Git 사용자 이름/이메일을 본인 설정으로 준비하세요. 공개 커밋에 사적인 이메일을 남기고 싶지 않으면 GitHub에서 제공하는 본인의 noreply 주소를 로컬 Git 설정에 사용하세요. 스크립트는 이름·주소를 만들어 넣거나 전역 설정을 수정하지 않습니다.

```sh
python scripts/publish_github.py --repo clearwrite
python scripts/publish_github.py --repo clearwrite --publish
```

첫 호출은 파일 목록과 실행 계획만 보여 줍니다. 두 번째는 이 폴더에 새 `.git`을 만들고 선택한 파일을 커밋한 뒤 **공개** 저장소를 생성·push합니다. 입력은 `name` 또는 `owner/name`입니다. 기존 `.git`이 있거나 Git 부모 저장소 안에 있으면 안전을 위해 중단합니다. 원격 생성 이후 push가 실패하면 원격 저장소가 이미 존재할 수 있습니다. 오류 후에는 상태를 직접 확인하고 재실행으로 기존 저장소를 덮지 마세요. 삭제·비공개 전환을 자동 수행하지 않습니다.

이미 Git으로 관리하는 복사본은 스크립트 대신 본인의 Git 흐름으로 파일을 검토하고 올리세요. README 안의 상대 링크는 GitHub에서 바로 작동합니다. HTML은 GitHub 파일 화면에서 실행되지 않으므로 다운로드해서 열거나 민감 자료가 없는지 확인한 뒤 별도 정적 호스팅을 선택하세요. 로컬 편집 UI를 공개 웹 서버로 배포하지 마세요.

## 릴리스와 재현

소스 ZIP에는 CLI, 스킬, 플러그인, 문서, 테스트, 비교 원문/결과를 함께 넣습니다. wheel은 독립 Python CLI만 설치하며 Codex 스킬은 소스 ZIP의 설치기를 사용합니다. 플러그인 ZIP은 정확히 하나의 플러그인을 포함합니다. SHA-256 체크섬으로 전송 후 파일이 같은지 확인할 수 있지만 배포자의 신원 서명은 아닙니다.

CI는 비밀 키 없이 테스트를 실행하도록 구성했습니다. 키가 필요한 서비스는 CI에서 호출하지 않습니다. 마켓플레이스/개인 플러그인 등록은 실제 호스트 설치·승인과 별개입니다. 사용자는 자신의 환경에서 새 세션을 열어 확인해야 합니다.

## 설치 취소

직접 설치한 스킬은 설치기가 출력한 `clearwrite` 폴더만 제거합니다. 플러그인은 먼저 호스트 UI에서 비활성화/제거하고, 자신이 추가한 ClearWrite 카탈로그 항목과 번들 폴더만 지웁니다. 전체 `.agents`, `.codex` 또는 다른 플러그인의 항목을 지우지 마세요. 이전 번들은 `.backup-<시각>` 폴더에 있습니다.
