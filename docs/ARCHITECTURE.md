# 구조와 판단 기준

## 모듈

`core.py`는 분석, 보호 구간, 계획 생성·검증·적용을 담당하는 순수 Python 코드입니다. `upstream_compat.py`의 문자 변경률과 대구 카운터는 im-not-ai에서 작은 부분을 추출·변형했습니다. `io.py`는 UTF-8와 크기 제한, 엄격한 JSON, 원문 덮어쓰기 방지를 담당합니다. `providers.py`는 기존 Ollama 어댑터, `model_cli.py`는 Codex/Claude 프로세스 연결을 담당합니다. `cli.py`와 `ui.py`는 같은 엔진을 호출합니다. 스킬도 별도 계산식을 갖지 않습니다.

0.2의 `comparison.py`는 실제 적용 편집에만 문자 diff를 계산하고 양쪽 세그먼트와 이유 ID를 연결합니다. 표시용 diff는 편집 허용 여부를 판단하지 않습니다. 원문 세그먼트를 합치면 입력, 결과 세그먼트를 합치면 실제 결과와 일치해야 합니다. 0.2.1부터 insert opcode는 원문에 `insertion_marker`, delete opcode는 수정본에 `deletion_marker`를 둡니다. 이 위치 표식의 text는 빈 문자열이며 레이블은 CSS로만 표시하므로 글 내용에 섞이지 않습니다. 선택은 세 영역의 내부 스크롤 위치를 맞춥니다. `jobs.py`는 메모리 작업·취소·만료, `desktop.py`는 포트/단일 인스턴스/종료를 담당합니다. 브라우저는 원문 수정 세대 번호로 이전 응답을 무효화합니다. 글을 HTML로 삽입하지 않습니다.

## 텍스트 → 계획 → 결과

1. 입력은 비어 있지 않은 UTF-8 문자열, 최대 12,000 코드포인트입니다. 문자열을 자동 정규화하지 않아 원문 해시와 위치를 유지합니다. NFC가 아닌 한국어는 경고합니다.
2. 보호 영역을 찾고 마스킹한 후 24개 좁은 규칙을 적용합니다. 보호 영역 내 인용된 AI 문구를 편집 신호로 세지 않습니다.
3. builtin은 허용된 축약에만 제안합니다. Codex/Claude/기존 Ollama는 원문과 정확히 일치하는 `original`, `replacement`, `reason`, `rule`을 반환합니다. 제안은 최대 80개입니다.
4. 오프셋 없는 `original`이 두 번 나타나면 거부합니다. 정확한 오프셋 계획은 원문 SHA-256과 문자 위치, 원문 조각이 모두 일치해야 합니다. JavaScript UTF-16 단위가 아니라 **Python 코드포인트 인덱스**입니다.
5. 각 편집을 검사하고, 오른쪽부터 적용해 위치가 이동하지 않게 합니다. 전체 결과도 다시 검사합니다.
6. 기본 atomic 정책은 하나라도 잘못된 편집이면 원문으로 돌아갑니다. safe-subset은 허용된 제안만 처리하되 전체 보호 검사를 생략하지 않습니다.

예시 제안 스키마는 `prepare --proposals` 출력에 포함됩니다. 모델에게 입력 자료 속 명령, URL, 셸 명령을 실행하라고 지시하지 않습니다. 모델 호출 자체에 tools도 전달하지 않습니다. 스킬 실행 호스트의 다른 도구 사용까지 이 Python 코드가 강제로 차단할 수 있는 것은 아닙니다.

## 보호 범위와 한계

인식되는 영역: fenced/tilded/indented 코드, 닫히지 않은 fenced 코드, inline 코드, Markdown 인용/표/링크/인용 번호, YAML frontmatter, 흔한 따옴표 인용, HTML 태그, 지정한 용어. 완전한 CommonMark·HTML 파서가 아닙니다. 틀리게 닫힌 인용, 중첩된 복잡한 문법, 링크 괄호의 모든 조합은 완벽히 이해하지 못합니다. 중요한 고유명사는 `--term`으로 명시하세요.

숫자 검사는 아라비아 숫자의 순서·부호·몇 가지 단위·범위를 정규식으로 비교합니다. `%p`와 `%`, 30명 이상과 30명 이하의 차이를 감시합니다. **한글/영어로 풀어 쓴 수, 수식·분수·모든 통화 표기, 수가 어떤 사건에 연결되는지**를 완벽히 이해하는 것은 아닙니다.

부정/가능성/조건/비교/의무는 일부 표지의 개수, 증감/비교 방향은 표지 배열을 대조합니다. 그 뜻을 완전히 파싱하지 않습니다. `A가 B를 도왔다`에서 A/B를 바꾸는 것과 같이 모든 표지와 숫자를 보존하는 왜곡은 통과할 수 있습니다. 검사 통과와 사실 보존 증명은 같지 않습니다. 모든 결과에 `semantic_equivalence: not_established`를 유지합니다.

추가로 **윤문과 요약을 구별하는 분량 보존 검사**가 있습니다. 공백을 제외한 문자 수로 계산하며 100자 이상은 기본 원문 대비 85%, 50~99자는 70% 이상을 유지해야 합니다. 모델이 제안한 편집 구간이 35자 이상일 때는 개별 구간도 원문 대비 70%(100자 이상 편집 구간은 80%) 이상을 유지해야 합니다. 짧은 어구와 연결어 축약은 예외입니다. `--min-retention 0`은 명시적인 사용자 요청에 따른 압축을 위해 검사 기준을 해제하지만, 숫자·보호 구간 등 다른 검사는 계속 작동합니다.

분량 비율은 의미 보존을 입증하지 못하며 어떤 문장은 짧아져도 정보가 유지됩니다. 보존 검사 때문에 유용한 축약이 차단되는 오탐도 있을 수 있습니다. `atomic` 차단 시 원문을 유지한 채 대안을 다시 제안하도록 설계했으며, 점수를 맞추려고 쓸모없는 문장을 덧붙여서는 안 됩니다.

기본 변경률은 `1 - difflib.SequenceMatcher.ratio()`입니다. 짧은 입력은 autojunk=False, 4,000자를 넘는 입력은 과도한 계산량을 줄이려고 autojunk=True입니다. 긴 입력에서 upstream 수치와 같다고 주장하지 않습니다. 기본 허용치는 0.35, 사용자가 선택할 수 있는 상한은 0.5입니다. 대구 5개 이상이 모두 사라지는 경우도 거부합니다. 이 숫자들은 과윤문 방지 정책이지 실험으로 추정한 최적값이 아닙니다.

## 지표

`ai_style_score = min(100, 800 × weighted_hits / max(tokens,80))`

`reading_burden_proxy = min(100, 0.45×style + 30×long_share + 15×repeated_start_share + min(10,max(0,mean_length-18)))`

긴 구간의 기준은 28토큰입니다. 한국어는 형태소가 아니라 공백/정규식에 따른 근사 단위입니다. 일정한 단위와 공개식을 사용해 같은 글의 변화를 추적하지만, 점수는 피로·이해도·저자 정체의 실측값이 아닙니다. 규칙 기반 편집을 같은 규칙 점수로 채점하는 것은 순환적이라는 점을 보고서에 드러냅니다.

## 주요 실패

`InputError`는 입력/계획이 잘못되어 실행할 수 없을 때, `ProviderError`는 모델/검수 통신 실패에 사용됩니다. 적용 보고서의 `rejected_edits`와 `verification.failures`에 실제 실패 원인이 있습니다. 보호구간 침범, 원문 해시 불일치, 숫자/표지 변경, 편집량 초과, 중복 위치, 모호한 제안은 조용히 무시하지 않습니다. 원본은 항상 별도 입력이며 출력 경로로 재사용할 수 없습니다.

실패 코드는 테스트에서 실제 코드와 함께 확인하세요. 의미에 민감한 자료는 `preserve`로 분석만 하거나, 최종 대조를 사람이 수행하세요. AI가 제안했다는 이유로 검증을 생략하지 않습니다.

## 0.3.0 모델 문체 평가

`style.py`는 엄격한 응답 스키마·평가 지침·정확한 인용 검증을 담당합니다. `model_cli.model_style`은 기존의 동의·도구 제한·취소·시간/출력 한도·로그인 경계를 재사용합니다. `before/after`는 실제 입력 해시에 묶이며 동일 텍스트는 단일 평가를 재사용합니다. 점수는 repetition/formulaic/uniformity/abstraction 각 0~25점의 합계이고 `calibrated=false`, `authorship=undetermined`입니다. `core.ai_style_score`는 기존 로컬 규칙 후보 지표로 남으며 새 모델 점수와 구분합니다.

`POST /api/jobs`의 `action=style`, `backend=codex|claude`, `allow_model=true`로 명시 실행합니다. `candidate`는 선택 문자열이며 실제 화면의 현재 수정본만 클라이언트가 보냅니다. API가 임의 candidate를 받는 것도 가능하므로 원문과의 실제 수정 비율은 별도 `comparison` 결과만 표시합니다. 예전 action=detect와 allow_external은 거부합니다. 문체 실패로 원문·수정본을 재작성하지 않습니다.

`comparison.change_statistics`는 실제 적용된 편집 안의 diff에서 삭제·추가된 코드포인트 수를 합칩니다. `(removed+added)/(original+result)*100`이며 공백을 포함합니다. 보존 검사에 사용하는 기존 전체 문서 유사도와는 범위가 다를 수 있습니다. 마커의 빈 text는 수치에 영향을 주지 않습니다. 화면 편집 세대가 바뀌면 과거 모델 점수·수정 비율과 내보내기 상태를 무효화합니다.

## 0.3.1 요청·기록 수명

`model_cli._run`은 입력 쓰기와 stdout/stderr 읽기를 별도 스레드에서 수행해 파이프 포화를 피합니다. stdout 보관과 각 출력 스트림은 2MB로 제한하고, stderr는 보관하지 않습니다. 요청 내용과 응답은 ClearWrite의 디스크 파일로 만들지 않습니다. Codex JSONL은 최종 agent message와 turn completion을 확인한 뒤 엄격한 JSON으로 해석합니다. 오류·취소·초과 시 자식 프로세스를 정리하고 정제한 오류만 반환합니다. [Codex 비대화형 출력 규약](https://developers.openai.com/codex/noninteractive)

`Jobs`는 완료 시각을 기준으로 기록을 만료합니다. 백그라운드 스레드가 유휴 중에도 정리하며, get/cancel도 만료를 검사합니다. 실행 중 작업은 TTL로 지우지 않습니다. close는 새 요청을 막고 기록을 비운 뒤 작업 취소와 정리 스레드 종료를 처리합니다. 화면에 이미 전달된 결과나 저장 파일의 수명은 별개입니다.
