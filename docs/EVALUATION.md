# 평가: 실제로 측정한 것과 아직 모르는 것

## 이번 릴리스의 실행

`data/corpus.jsonl`에는 웹 원문 8개(역사적 저자 글4, 현대 사람이 편집하는 Python 문서4), 개발 대화에서 생성한 AI 글8, 안전장치용 스트레스 글4가 있습니다. 각 항목의 출처·구분·시각·정규화·해시는 원문과 함께 저장했습니다. 현재 편집되는 문서가 AI 도움을 전혀 받지 않았다고 확인할 수 없으므로 역사적 원저자의 글과 나눕니다.

대조군은 원문 유지(noop), 기본 편집(builtin), 현재 개발 대화에서 생성한 문맥 편집 제안의 재현(session_editorial_replay)입니다. 20×2+16=56회 적용을 실행합니다. replay는 실제 모델 제안을 파일로 남기고 Python 엔진으로 적용한 결과지만, 자동으로 설치된 Codex/Ollama를 호출해 얻은 결과는 아닙니다. 생성 시점·프롬프트 설명은 `generation_protocol.json`에 있습니다. API seed/log를 지어 넣지 않았습니다.

작은 탐색용 표본이며 모델 개발자가 예문과 편집을 모두 보았습니다. 무작위·사전등록·독립 평가가 아닙니다. 전부 낮은 점수를 만들기 위한 합성 예문만 쓰지 않고 별다른 수정이 없는 AI 문장도 포함했습니다. 실제 숫자는 `reports/demo`에 있습니다. 스트레스 표본은 안전장치 확인용으로만 보고 효과 평균에서 제외합니다.

## 0.1.1 분량 보존 실험

사용자 평가에서 예시 문장이 지나치게 짧아지는 문제가 지적되어 문서 전체와 편집 구간의 분량 보존 검사를 별도로 추가했습니다. 이로 인해 실제 비교에서도 일부 윤문 제안이 차단됩니다. 특히 영어 AI 참고군의 두 제안은 문맥을 지나치게 압축할 가능성이 있어 기본 `atomic` 정책에서 원문을 반환합니다. 이 결과는 "모든 윤문이 성공했다"고 해석할 수 없으며 오탐 여부도 독립 평가가 필요합니다.

분량 보존은 인지부하 감소에 대한 객관적 지표가 아니라 과잉 편집을 막는 보조 장치입니다. 글자 수만 비슷하게 만든 후보가 원문보다 자연스럽거나 정확하다고 단정하지 않습니다. 수정본이 길어져도 새 사실·근거를 만들어 넣어서는 안 됩니다.

## 해석할 수 없는 결론

내부 점수 감소를 AI 탐지 회피율, 사람 같은 문체의 증명, 피로도 감소율, 정확한 저자 확률로 표현하지 않습니다. 역사적 문학과 최신 기술 문서는 문장 길이·장르·시대·번역 특성이 다릅니다. 같은 언어/주제 안의 전후 비교도 의미 보존을 별도로 확인해야 합니다. 낮은 스타일 점수의 AI 글과 높은 점수의 사람 글이 모두 가능합니다.

현재의 보호 검사는 일부 규칙을 통과한 것이며 의미 동등성 검증은 아닙니다. 명사/주체 바꾸기 등 알려진 사각지대도 테스트에 포함합니다. 평균만 제시하지 않고 차단·무수정·개별 원문/결과를 남깁니다.

## 모델 문체 평가

0.3.0은 별도 AI 탐지기 연결을 제거하고 선택한 Codex·Claude의 네 문체 항목 평가를 제공합니다. 실제 인용·해시 검증과 점수 합산이 모델 판단의 정확도를 입증하지는 않습니다. AI 작성 확률, 사람 작성 인증, 탐지 회피율로 해석하지 않습니다. 장르와 모델에 따른 일관성은 별도 평가가 필요합니다. 오프라인 벤치마크는 기존 편집 재현만 수행하며 모델 문체 요청을 자동 실행하지 않습니다. 실제 연결 검사와 모의 계약 검사는 릴리스 증거에서 구분합니다.

## 실제 독자 평가 설계

우선 **읽기 편함**, **이해 정확도**, **정보 보존**을 따로 평가합니다. 표본을 늘릴 때는 주제/장르/길이와 독자의 배경지식을 맞추고, 학습용과 공개용을 분리합니다. 같은 내용을 두 번 읽으면 학습효과가 생기므로 한 사람이 같은 문서의 두 버전을 모두 읽지 않도록 버전을 교차 배정하는 것이 좋습니다.

제안하는 다음 단계는 한국어 정보 글 30개 이상, 독립 참가자 12명 이상의 탐색 연구입니다. 이는 검정력 계산을 거친 확정 표본 수가 아닙니다. 결과가 중요하면 효과 크기/변동성을 파일럿으로 추정하고 분석 계획을 미리 정하세요. 각 문서에 대해 읽기 시간, 이해 문항 2~3개, 핵심 회상, 다시 읽은 횟수, 주관적 부담1~5, 중요한 누락/왜곡을 수집합니다. 윤문 전후 의미 판정자는 버전 정보를 보지 않도록 합니다.

분석 단위는 개별 문서·독자이며 문단을 독립 참가자처럼 세지 않습니다. 가능한 경우 독자/문서 수준의 변동을 반영하고 신뢰구간과 무수정·악화 사례를 제시합니다. 단순히 더 짧거나 더 빨리 읽었다는 이유만으로 좋은 결과라고 결론짓지 않습니다.

동봉된 `blind-review.html`은 5개의 실제 변경 사례에서 A/B 선호도를 살피는 **탐색용 양식**입니다. 엄밀한 위 설계를 이미 실행한 것이 아니고 현재 참여자는 0명입니다. 타이머/이해 문항도 포함하지 않습니다. 결과는 서버로 전송하지 않고 직접 JSON으로 저장합니다. 실제 독자 응답이나 개인 글은 공개 저장소에 자동 추가하지 마세요.
